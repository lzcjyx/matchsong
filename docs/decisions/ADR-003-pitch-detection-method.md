# ADR-003: 音高检测方法 —— YIN（纯 Kotlin）

- **状态：** Accepted
- **日期：** 2026-07-30
- **决策人：** Coding Agent（M-1.6）
- **关联文档：** `docs/experiments/pitch-detection-results.md`、`docs/experiments/spike-results.md`、`docs/research/academic-research.md`

## 背景

M-1.5 Spike 实测三种音高检测方法（YIN / 朴素自相关 ACF / FFT 频谱主峰），输入为合成信号（纯正弦 130-1046Hz、音阶、静音、白噪声、削波、说话近似），帧长 2048@44.1kHz。

## 决策

**MVP 音高检测采用 YIN（de Cheveigné & Kawahara 2002），纯 Kotlin 实现：**

- 工作频率范围：**65Hz (C2) ~ 1046Hz (C6)**；
- 帧长 2048（约 46ms @44.1k），步进 1024（50% 重叠）；
- 无效帧过滤：RMS < 0.01（静音）或 YIN 可信度 < 0.5 或频率越界 → 丢弃；
- 后续音域统计使用有效帧轨迹（稳定性指标在 M5 定义）；
- **不引入 TFLite/CREPE/NDK**（MVP）。

## 理由（实测数据）

1. **唯一在全部干净信号上零错误**：正弦 130-1046Hz 中位误差 < 0.03%（ACF 最差 89%，FFT <0.15%）；
2. **抗削波**：削波 440Hz 仍检出 440.03Hz（0.007% 误差）；ACF 同场景锁定子谐波；
3. **拒噪**：静音、白噪声正确判为无音（ACF/FFT 白噪声均误报）；
4. **性能余量充足**：~1.04ms/帧（桌面 JVM），帧预算 46ms，余量 45 倍；即使移动端弱 5-10 倍仍满足实时；
5. 纯 Kotlin 满足 PLAN §2.2"性能证明不足前不引入 C++/NDK"；
6. YIN 为声学分析事实标准（pYIN 的基础），有论文依据 [S1]。

## 后果

- **积极**：音高轨迹质量高，音域/稳定性指标建立在可靠 F0 上；实现简单（差分函数 + CMND + 抛物线插值），无模型依赖；APK 体积不受影响。
- **消极**：YIN 对非周期性信号（噪声）会输出低可信度结果，必须依赖过滤规则；对真实人声（颤音/滑音）表现待实测。
- **成本**：M5 实现时需完成帧管线、过滤、轨迹平滑；可选的 pYIN 式 HMM 平滑留作 M5 备选增强。

## 备选方案与拒绝理由

- **ACF（朴素自相关）**：拒绝。子谐波锁定（220→73.4Hz=220/3、440→110Hz=440/4）为教科书级缺陷，白噪声误报；修复需 CMND，等价于 YIN。
- **FFT 频谱主峰**：拒绝作为主方法。主峰≠基频（谐波丰富的真实人声会锁倍频），白噪声误报；仅适合纯音场景，可作为 YIN 的交叉验证辅助（可选）。
- **CREPE（TFLite）**：推迟。无 Spike 实测支持其必要性，模型体积/功耗/实时性未验证；若 M5 真机人声实测 YIN 不足，再评估。

## 待复核条件

- M1 后用真人人声（男/女声、环境噪声）实测；若准确率/未识别率不达标 → 评估 pYIN 平滑或 CREPE。
