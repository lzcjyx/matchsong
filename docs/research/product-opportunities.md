# 产品机会分析 — matchsong

> M-1.3 交付物。基于 `competitor-research.md` 的调查结果，综合分析市场空白、本产品与唱歌评分产品的差异、"唱几句后推荐歌曲"的直接竞争态势，并提出至少三个差异化方向与 MVP 定位建议。
> 标注约定：`[推测]` 表示基于调查的合理推断。

---

## 1. 核心问题研判：是否存在"唱几句后推荐适合你音域的歌"的直接竞品？

**结论：存在，但不充分。该需求已被多个产品不同程度、不同路线地实现，尚无一款产品同时满足"端侧隐私 + 可解释音域匹配 + 中文曲库 + 演唱负担量化"的完整体验。**

### 1.1 已实现该诉求（或其变体）的产品

| 产品 | 实现路线 | 与本产品诉求的契合度 |
|---|---|---|
| **Sing Whiz** | 60s 测音域 → 声部 → 歌手匹配 + 歌曲推荐 | 高（直接竞品）。但被用户反映"测不准"，无可解释性，曲库/语言偏英文，隐私未明示 |
| **Singing Carrots** | 浏览器测音域 → 5000 歌手匹配 → 按音域/难度搜索歌曲 | 高（直接竞品）。偏 Web 自练工具，需登录，无中文曲库导向 |
| **KaraFun Vocal Match** | 录几秒人声 → 对曲库每首歌给匹配度评分 | 中高（直接竞品，但只给分数不给解释，不告诉升降调建议） |
| **Vocaberry VocalRange** | 演唱检测音域 → 显示适配歌曲洞察 | 中（直接竞品，但推荐闭环较弱） |
| **Simply Sing** | 测音域 → 把所有歌**移调适配**到用户音域 | 低（理念相反：改编歌曲而非筛选适唱歌曲，破坏原调） |
| **Singa** | 用户**手动**移调适配音域 | 低（不测音域、不自动推荐，纯手动工具） |

### 1.2 "不充分"的具体含义（即机会窗口）

1. **可解释性缺位**：KaraFun Vocal Match 只给一个 72%/93% 匹配分数，不告诉用户"为什么匹配、差在哪、建议升降调几度"。Sing Whiz 给推荐但不解释依据。本产品 PLAN §2.1 明确要求"可解释的音域推荐"——这是已被验证的空白。
2. **演唱负担未量化**：现有产品最多比音域上下限，几乎无人量化"高音持续时间、旋律跳进难度、舒适音区占比"等多维负担（PLAN §2.1 第 7、8 项）。`[推测]` 这是因多数产品定位 K 歌/社交，不需要精细适唱度建模。
3. **端侧隐私缺位**：A 类直接竞品均未明确承诺"原始音频本地处理、不上传"。唯一定位隐私优先的 SingMeter（E 类）却**不做歌曲推荐**。把"端侧隐私"和"音域推荐闭环"组合起来是空白点。
4. **中文曲库与中文用户语境缺位**：Sing Whiz / Singing Carrots / KaraFun / Simply Sing 均偏英文曲库与欧美歌手匹配。国内 K 歌产品（全民 K 歌、唱吧）曲库庞大但**完全不做音域推荐**。中文歌的音域/适唱度数据 + 中文歌手匹配是空白。
5. **声部绝对化陷阱**：Sing Whiz 等强调"你是 Soprano/Tenor"的声部标签，而本产品 PLAN §2.1 明确**不以识别音色类型/声部为卖点**，避免"你是专业男高音"这类无依据绝对结论。这是产品价值观层面的差异点。

## 2. 本产品与唱歌评分产品的本质差异

唱歌评分产品（Smule、StarMaker、WeSing/全民 K 歌、唱吧、Rate My Singing）回答的是 **"你这次唱得好不好"**；本产品回答的是 **"你适合唱什么歌"**。二者输入相似（都是唱几秒到几分钟），但输出目标、算法焦点、用户心智完全不同。

| 维度 | 唱歌评分产品（B/E 类） | 本产品（matchsong） |
|---|---|---|
| 核心问题 | "我唱得几分？" | "我适合唱哪首歌？" |
| 输入 | 跟唱某一首**指定**歌曲 | 自由唱 15-30s（不限曲目） |
| 算法焦点 | 音准贴合度、节奏、表现力 → 综合分数 | 音域/舒适音区/音高稳定性 → 与**歌曲音域特征**匹配 |
| 输出 | 一个分数 + 排行榜/社交 | 适唱歌曲列表 + 可解释匹配理由 + 升降调建议 |
| 评价对象 | 用户的**演唱表现** | 用户的**声音特征**与**歌曲特征**的契合度 |
| 社交导向 | 强（作品发布、挑战、直播） | 弱（MVP 可不做社交） |
| 原始音频 | 上传持久化（作品回放所需） | 本地优先，不默认上传（PLAN §3.2） |
| 失败心智 | "我唱砸了，分数低" | "这首歌不适合我音域，换一首" |
| 复用关系 | 评分产品**需要**本产品的能力做前置筛选：先知道适合唱什么，再去评分 | 反之不然 |

**关键洞察**：唱歌评分产品解决"唱得好不好"，本产品解决"该唱什么"。二者非替代关系，而是**上下游**关系。本产品可作为评分/K 歌产品的前置决策层——"先让 matchsong 告诉你适合唱哪首，再去全民 K 歌唱并评分"。这既是差异，也是潜在合作/导流逻辑。`[推测]`

**与 AI 声乐教练产品（C 类）的差异**：教练产品回答"我该怎么练好"，本产品回答"我适合唱什么"。教练产品的分析用于训练反馈，本产品的分析用于歌曲匹配。教练产品不做歌曲推荐，本产品不做训练课程。

## 3. 差异化方向（至少三个）

### 方向一：可解释的音域适唱度推荐（对标 KaraFun/Sing Whiz 的"黑箱匹配"）

- **现状痛点**：KaraFun Vocal Match 只给一个匹配度分数，不解释；Sing Whiz 给推荐但被用户反映"测不准"、无依据。
- **差异化做法**：每次推荐都输出**人可读的匹配理由**——
  - "你的舒适音区 G3–D4，这首歌主旋律音区 A3–E4，84% 落在你舒适区内，高音 E4 你曾稳定唱到"；
  - "这首歌最高音 G4 超出你稳定最高音 F4 一个音，建议降调 1 半音或谨慎尝试"；
  - 量化展示 PLAN §2.1 的全部 10 项依据（稳定最低/最高音、舒适音区、音高稳定性、歌曲最低/最高音、主旋律音区、高音持续、跳进难度、升降调建议、用户偏好）。
- **护城河逻辑**：可解释性 = 信任 = "测不准"痛点的解药。这是 Sing Whiz 负面反馈集中点，也是 PLAN §3.2"无依据不得宣称准确"价值观的产品化。

### 方向二：端侧隐私优先 + 原始音频不持久化（对标全行业上传惯例）

- **现状痛点**：B 类 K 歌产品普遍上传并持久化原始人声（作品回放所需）；A 类直接竞品未明确隐私承诺；唯一隐私优先的 SingMeter 不做推荐闭环。
- **差异化做法**：
  - 严格遵循 PLAN §2.2"优先本地音频处理"、§3.2"未经用户明确同意不上传原始音频、默认不永久保存原始录音"；
  - 录音→端侧 PCM 分析→提取音高轨迹/音域特征→**丢弃原始音频**，仅持久化特征向量；
  - 以"你的声音特征留在你手机里"为明确卖点（对标 SingMeter 已验证的隐私优先诉求，但补上 SingMeter 缺失的推荐闭环）。
- **护城河逻辑**：唱歌是私密行为，嗓音是生物特征。在 GDPR/个保法语境下，"不存你的原始声音"是可宣传的信任资产，且与 K 歌社交类产品形成鲜明对比。

### 方向三：中文曲库 + 中文歌曲音域特征数据（对标英文曲库竞品）

- **现状痛点**：Sing Whiz、Singing Carrots、KaraFun、Simply Sing 均偏英文曲库与欧美歌手匹配；国内 K 歌产品曲库虽大但无音域推荐。
- **差异化做法**：
  - 建立**可验证、可更新的中文歌曲特征数据**（PLAN M-6）：每首歌标注最低音、最高音、主旋律音区、高音持续段、旋律跳进难度、建议升降调范围；
  - 中文歌手音域匹配（对标 Singing Carrots 的 5000 歌手库，但做中文歌手）；
  - 支持用户语言/风格/歌手偏好（PLAN §2.1 第 10 项）。
- **护城河逻辑**：数据冷启动是真实壁垒，但中文歌曲音域数据是英文竞品不会做、国内 K 歌产品没做的夹层空白。先发者可形成数据资产。

### 方向四（加强项）：演唱负担的多维量化（超越"音域上下限"比拼）

- **现状痛点**：现有竞品最多比音域上下限（最高音/最低音），几乎无人量化"高音持续时间、旋律跳进、舒适音区占比"。
- **差异化做法**：把 PLAN §2.1 第 7、8 项（高音持续时间、旋律跳进和演唱难度）纳入适唱度模型，区分"音域够得着但高音段太长会累"与"音域够得着且高音短促"。
- **护城河逻辑**：从"能不能唱到"升级到"唱得累不累"，是音域推荐从粗到细的产品进化方向，竞品尚未覆盖。

### 方向五（定位项）：明确拒绝"声部/音色类型"绝对化标签

- **现状痛点**：Sing Whiz 等以"你是 Soprano/Tenor"为核心输出，易诱导"你是专业男高音"等无依据结论（PLAN §2.1 明令禁止）。
- **差异化做法**：只输出音域范围 + 舒适音区 + 适唱歌曲，**不**输出绝对声部判定，或仅作参考性提示并标注局限。
- **护城河逻辑**：规避医学/职业性误导的法律与伦理风险，符合 PLAN §3.2"不得虚构/无依据宣称"的工程纪律，建立"克制品格"的产品调性。

## 4. MVP 定位建议

### 4.1 一句话定位

> **唱 15-30 秒，本地分析你的音域与音高稳定性，可解释地推荐适合你音域的中文歌曲，并给出升降调建议——原始声音不离开你的手机。**

### 4.2 MVP 核心能力边界（对齐 PLAN §2.1）

必做：
1. 15-30s 演唱录音 + 端侧 PCM 分析；
2. 稳定最低音、稳定最高音、舒适音区、音高稳定性输出；
3. 基于歌曲音域/主旋律音区/高音持续/跳进难度的适唱度评分 + 可解释理由；
4. 升降调建议；
5. 中文歌曲特征数据（小而精的初始集，可更新）；
6. 原始音频本地处理、不默认持久化、不上传。

不做（MVP 边界外）：
- 声部/音色类型绝对判定（PLAN §2.1 禁止）；
- K 歌社交、作品发布、直播、挑战；
- 唱歌评分（与 B 类产品正交，非本产品目标）；
- AI 声乐教练训练课程（与 C 类产品正交）；
- 自动修音/效果（与 D 类产品正交）；
- 把歌曲移调适配（Simply Sing 路线）——本产品保持原调、筛选适唱。

### 4.3 竞争定位图

```
                     原始音频上传持久化
                           │
            Smule · StarMaker · WeSing · 唱吧
                           │
   评分/社交 ──────────────┼────────────── 推荐/适配
                           │
            RateMySinging  │   Sing Whiz · Singing Carrots
            SingingCoachAI │   KaraFun VocalMatch · Vocaberry
                           │   Simply Sing(改编) · Singa(手动)
                           │
                     端侧本地处理/不持久化
                           │
                     SingMeter(仅分析)
                     ★ matchsong (目标象限)
```

本产品目标象限：**右下（推荐/适配 + 端侧本地处理）**，目前仅 SingMeter 占据"端侧"但它在左侧"仅分析"而非右侧"推荐"。**matchsong 是首个将"端侧隐私"与"可解释音域推荐"组合的产品**（在中文曲库语境下）。

### 4.4 风险与前提（需后续 Spike 验证，非本次研究结论）

- 端侧 YIN/pYIN 音高检测在中端 Android 设备上的精度与性能 → M-1.5 Spike 验证；
- 中文歌曲音域特征的获取与版权合规 → M-6 数据系统解决；
- "可解释"话术需有算法依据，不得滑回 Sing Whiz 式的"测不准+无解释" → M-7 推荐引擎的可解释性约束。
- `[推测]` 用户是否愿意为"音域推荐"独立于 K 歌产品单独使用一个 App，需在 M0/M8 用研验证；若不成立，可考虑作为 K 歌产品的前置工具或模块化输出。

## 5. 结论摘要

1. **"唱几句后推荐适合你音域的歌"不是空白市场**：Sing Whiz、Singing Carrots、KaraFun Vocal Match、Vocaberry 已不同程度实现。
2. **但存在明确空白**：可解释性、端侧隐私、中文曲库、演唱负担量化、声部绝对化规避——五条差异化路线，本产品可同时占据多条。
3. **与唱歌评分产品是上下游而非竞争**：评分问"唱得好不好"，本产品问"该唱什么"，可形成"先 matchsong 选歌、再 K 歌评分"的互补关系。
4. **最强劲直接竞品**：Sing Whiz（用户量大但测不准、无可解释性）与 KaraFun Vocal Match（有匹配度但黑箱）。二者共同弱点是"不解释 + 隐私未承诺"，正是本产品双差异化着力点。
5. **隐私优先已有先例**：SingMeter 证明"端侧音域分析 + 不存原始音频"可行，本产品在此之上加推荐闭环即形成差异。
6. **MVP 定位**：端侧、可解释、中文曲库、原调筛选（非移调适配）、不做声部绝对判定、不做评分社交。
