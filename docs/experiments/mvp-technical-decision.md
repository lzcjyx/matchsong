## 1. 三种推荐方向比较

| 维度 | A. 音色推荐 | B. 音域推荐（本项目） | C. 综合推荐 |
|---|---|---|---|
| 输入 | 15-30s 演唱 | 15-30s 演唱 | 同 B + 偏好 |
| 核心算法 | 音色嵌入/分类（需大模型或专业标注） | YIN 音高轨迹 → 音域/舒适区/稳定性 | B + 加权融合 |
| 可解释性 | 低（"你的声音像 XX"无法解释） | **高**（"你稳定唱到 C4-G4，推荐该区间歌曲"） | 中 |
| 端侧可行性 | 低（需 TFLite/CREPE 级模型） | **高**（纯 DSP，已实测 1ms/帧） | 中高 |
| 研究依据 | PLAN §2.1 禁止绝对结论（"你是男高音"） | 音高/音域是客观可测物理量 | 依赖 B 成立 |
| 风险 | 模型数据需求大、准确率无法验证 | 低，物理量可直接验证 | 中 |
| 差异化 | 竞品多（AI 声乐教练） | **稀缺**（"唱几句推荐适合音域的歌"，竞品研究确认直接竞品少且不充分） | 依赖差异化 |

## 2. 决策：选择 **B. 音域推荐**（与 PLAN §2.1 MVP 定位一致）

理由：

1. **可解释**：音域推荐的全部输入（最低音/最高音/舒适区/稳定性/歌曲音域/负担）都是可测量、可解释的物理量，符合 PLAN"优先实现可解释的音域推荐"；
2. **端侧可行**：M-1.5 实测 YIN 纯 Kotlin 即可高精度完成核心分析（<0.03% 误差，1ms/帧）；
3. **风险最低**：不需要大模型、不需要后端、不依赖无法验证的音色分类；
4. **差异化**：竞品研究确认"唱几句后推荐适合音域的歌"存在但竞争不充分，是可切入的空隙；
5. **非目标明确**（见下）。

### MVP 非目标（明确不做）

- 不做音色类型识别与绝对化结论（男高音/女中音/职业歌手/音色与某歌手一致）——PLAN §2.1 禁止；
- 不做唱歌评分（音准打分、K 歌社交）——竞品研究明确评分产品与本产品定位不同；
- 不做演唱技巧教学（共鸣/气息/咬字反馈）；
- 不识别嗓音疾病。

## 4. 主要技术风险（按严重度）

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | 真实人声 F0 准确率未实测 | 核心指标可能达不到预期 | M1 后真机采集人声样本复测；pYIN/HMM 平滑作为备选（M5） |
| 2 | M-1.4 运行验证 BLOCKED | 录音链路端到端未验证 | 连接设备补测；M3 前必须完成 |
| 3 | 舒适音区无统一标准 | 推荐依据的主观性 | M0 SPEC 明确定义（如 80% 音高分布区间） |
| 4 | 设备采样率/麦克风差异 | 跨设备不一致 | 运行时探测采样率、降级；M10 设备矩阵 |
| 5 | 歌曲音域数据来源 | 推荐质量依赖曲库标注 | M6 建立可验证的歌曲特征数据 |

## 5. 进入 M0 的建议

1. SPEC 中固化"音域推荐"定义与非目标清单（§2）；
2. 定义舒适音区/稳定性/演唱负担的可计算指标；
3. 设计可解释推荐输出模板（如"你的稳定音区 C3-A3，推荐以下 5 首"）；
4. 确定歌曲特征数据的最小字段集（最低音/最高音/主旋律区/难度/调性）；
5. 将"真机人声验证"列为 M1 退出条件之一。
