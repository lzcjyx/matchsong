# 回滚计划（Rollback Plan）

- **版本：** 0.1.0 (1)
- **日期：** 2026-08-01
- **状态：** 就绪（Play 轨道策略 + 版本策略已定，无需代码变更）

## 1. 回滚策略（Play Console）

| 场景 | 动作 | 说明 |
|---|---|---|
| 发布后发现问题（Internal/Closed） | **保留旧版本轨道**：将上一版本重新设为 Track 发布 | Play 支持同一 Track 多版本并存，回滚 = 重新激活旧 AAB |
| 紧急回滚 | 在 Play Console 将受影响版本**暂停/下架**，旧版本恢复为默认 | 用户收到旧版本更新；数据（Room v3）向下兼容问题见 §3 |
| 灾难级 | 关闭测试轨道 / 下架应用 | 仅严重隐私/安全事件（P0）时使用 |

## 2. 版本策略

- `versionCode` 单调递增（当前 1），`versionName` 语义化（0.1.0）；
- 每次发布前构建必须保存：AAB + `mapping.txt`（`app/build/outputs/mapping/release/`，M11.1）——崩溃符号还原必备；
- 上一发布构建（APK + mapping）归档至 `docs/release/archives/`（发布时执行）。

## 3. 数据兼容性

| 风险 | 说明 | 缓解 |
|---|---|---|
| Room 降级 | 回滚到旧版本时，新版本若已升级 schema（v1→v2→v3 已有 Migration），**旧版本无法打开新 schema 数据库** | ① 发布前确认无破坏性 Migration；② 紧急回滚时引导用户清除数据（设置→删除全部数据）或重装；③ 历史数据丢失风险在发布说明中披露 |
| DataStore | 键值存储，旧版本读取新键安全（忽略未知键） | 无 |
| 文件缓存 | cache 目录，系统/启动清理兜底（M3.5-2/M9.2） | 无 |

## 4. 回滚演练（发布前执行）

- [ ] 模拟器安装 v0.1.0 → 执行一次完整流程 → 记录数据；
- [ ] 安装新版（同签名覆盖）→ 验证升级无数据丢失；
- [ ] 回滚（重装旧版 AAB 派生 APK）→ 验证可启动；数据库兼容性按 §3 处理；
- [ ] 验证崩溃还原：用新版本 mapping.txt 反混淆一份崩溃堆栈（可选）。

## 5. 责任人

- 回滚决策与执行：产品负责人（Play Console 权限持有者）；
- 技术验证：Coding Agent（本仓库）。
